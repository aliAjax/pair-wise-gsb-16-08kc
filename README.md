# 职业听力监护台

噪声作业岗位的职业健康听力监护工作台：按员工、左右耳、0.5~6 kHz 保存气导听阈；
首次有效检查作为基线单独留档，年度复测以基线判定标准阈移（STS），命中即列入
30 天复查名单。

## 技术栈

React 19 + Vite + TypeScript + 原生 CSS（无第三方图表库，听力图为内联 SVG），
数据持久化在浏览器 localStorage。

## 本地运行

```bash
npm install
npm run dev          # http://localhost:5101
npm run build        # 类型检查后打包
npm test             # 判定规则 / 名单 / 种子数据一致性冒烟测试
```

## 阈移判定规则（基线 → 年度复测，单耳）

- 相邻两个频点（0.5-1 / 1-2 / 2-3 / 3-4 / 4-6 kHz）平均听阈提高 **≥ 10 dB**
- 任一频点听阈提高 **≥ 15 dB**

满足任一条件即列入待复测，名单显示耳别、频点、提高值与超出值。

## 业务规则

- **基线只建一次**：首次有效检查保存后任何新结果都不能覆盖；录入页禁用已有基线的基线选项。
- **复测不覆盖基线**：年度复测作为独立记录保存，与基线同图对比（基线虚线、复测实线、复查点线）。
- **30 天复查**：命中阈移自动生成待复测任务，期限 = 复测日 + 30 天，可登记/修改预约日；
  逾期红色、临期橙色。
- **完成前不算合格**：有未完成复查任务的员工不进入年度合格名单；
  复查结果单独留档，完成后恢复合格资格，原复测曲线保留。
- **筛选全局联动**：姓名/工号/岗位搜索、车间与状态筛选同时影响顶部指标、
  待复测名单、合格名单与总览曲线。
- **关闭再打开数据仍在**：所有记录变更即时写入 localStorage；可用“恢复演示数据”重置。

## 代码分层（记录 / 判定 / 保存 / 页面分开）

```
src/domain/
  types.ts       数据模型（员工、检查、阈移命中、复查任务）
  hearing.ts     纯逻辑：频点定义、evaluateShift 阈移判定、PTA、日期
  selectors.ts   纯逻辑：员工状态汇总、指标、待复测/合格名单
  storage.ts     localStorage 读写 + 演示数据
src/state/
  useHearingStore.ts  记录动作（建基线/复测/复查、预约登记），调用判定并落库
src/components/      页面组件（录入、名单、听力图、详情）
scripts/smoke.ts     纯逻辑冒烟测试
```
